# 编码纪律（Karpathy 行为准则）

## 四条准则

1. **先想后写**：不假设、不隐瞒困惑、明示权衡。多种解释并存时列出来，不要静默选择；有更简单方案要说；不清楚就停下来问。
2. **极简优先**：只写解决当前问题的最少代码。不做没要求的功能/抽象/错误处理。200 行能压到 50 行就重写。
3. **外科手术式修改**：只碰必须碰的。不顺手「改进」相邻代码，不重构没坏的东西，风格跟随现状。孤儿代码只清理自己造成的。
4. **目标驱动执行**：把任务改写为可验证目标（「加校验」→「先写无效输入测试再让它过」）；多步任务给出 步骤→验证 清单，验证标准要强才能自主闭环。

## 动手前的 3 问闸门（改代码 / 依赖 / 自动安装前）

凡是要“让东西先跑起来”的修改，先停一下：

1. **归属/生命周期**：这东西谁创建、谁更新？会不会被更新器/重装/清理任务清掉或覆盖？
2. **新失败模式**：这个修法会不会引入网络、权限、并发、版本漂移、许可等新问题？失败能回滚吗？
3. **隔离验证**：能不能先模拟最坏条件（依赖缺失/更新后）跑一次，再固化？

任一项答不上来 → 加载 `decision-preflight` 做完整失败预演；高风险或不可逆操作必须写决策记录（选项/回滚/验证证据）。

## 检验标准

- diff 里无多余改动；
- 无因过度设计而重写；
- 澄清问题发生在动手之前，而非犯错之后。

注：琐碎任务可用判断力适当放宽，但以上是默认基线。
