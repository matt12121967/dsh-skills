# 决策前置检查（三思 / premortem）

## 何时必须用

- 改受管环境：DSH runtime、Python site-packages、PATH、插件、技能目录
- 装/升级依赖，或写“自愈/自动安装/自动更新”逻辑
- 改定时任务、自动化、外部服务、凭证、不可逆文件操作
- 用户问“要不要做 A”“A 会不会有新冲突”“哪种更好”
- 准备把某个做法写进技能/默认流程之前

## 六步检查（每步有完成标准）

1. **定义决定**：一句话写清“要改变什么、为什么现在改、最坏后果是什么”。完成标准：能说清 blast radius（会影响哪些文件/环境/会话）。
2. **列选项**：至少 3 个——不做/手工、最小改动、彻底方案；找出直觉默认项，并主动质疑它。完成标准：每个选项写一行代价。
3. **预演失败（premortem）**：假设 30 天后失败了，列出具体原因。逐项过下面的“冲突面清单”。完成标准：每个维度都有结论或“不适用”。
4. **用探针代替假设**：读官方文档/源码、跑只读命令、看时间戳与安装记录、在隔离状态验证。完成标准：关键未知项有证据（命令输出/文件路径/版本号），不靠“之前能用”。
5. **选最小变更并定回滚**：优先本地化、可逆、不写受管环境；拒绝隐式副作用。完成标准：写下回滚命令/恢复步骤。
6. **隔离验证后固化**：模拟最坏条件（依赖被删/更新后）跑一次；成功才更新技能、文档、教训库。完成标准：验证证据 + 文档更新 + 清晰的失败提示。

## 冲突面清单

- **生命周期/归属**：谁创建、谁更新、谁删除？会不会被更新器/重建清掉？
- **依赖与网络**：是否引入联网、PyPI、外部服务、版本漂移？离线时怎么办？
- **权限与安全**：是否写受管目录、改全局环境、执行远程代码？供应链/许可是否合规？
- **并发**：多会话/多进程同时跑会不会抢锁、互相覆盖？
- **可逆性**：失败后能否一键回滚？不可逆操作是否有快照？
- **成本/性能**：体积、耗时、积分、维护成本是否可接受？
- **可观测/可测试**：失败时错误是否一眼看懂？能否在隔离状态复现？
- **版本兼容**：运行时升级（如 Python 3.12→3.15）后是否仍可用？

## 红旗（出现即停下来重想）

- 在无人值守脚本里自动 `pip install` / 自动更新 / 自动下载
- 直接修改 DSH runtime、系统 PATH、全局 site-packages
- “之前一直能用”当作证据，没查生命周期（更新器是否清掉）
- 还没隔离验证就写进技能/默认流程
- 不可逆操作没有快照/回滚
- 用“加个自愈”掩盖根因，制造新的失败模式

## 决策记录模板（可贴进任务/技能/教训）

```
决定：
不可逆点 / blast radius：
选项：A … / B … / C …
预演失败：生命周期 …；依赖/网络 …；权限 …；并发 …；回滚 …
选择与理由：
验证方式（隔离条件 + 证据）：
回滚：
```

- `engineering-cybernetics`：闭环、反馈、稳定性，用于判断“该不该自动化/加反馈”

## 失效条件

- 单行 typo、纯读取、明确 trivial 的操作可跳过
- 紧急止损（正在大量丢数据/服务已挂）先止血，事后补做预演与记录
