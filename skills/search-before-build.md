# 先检索，再动手

自研是最后手段，不是默认选项。绝大多数「帮我做个 X」在本地、在生态目录、或在公开仓库里已经有七成答案。

## 三行检索记录（缺一行不许动手）

1. **本地**：`where.exe <名字>`、PATH、已装的插件与技能目录里，有没有等价物。
2. **生态目录**：这个领域的注册表——harness 自己的插件市场、语言包管理器、带 topic 的仓库、领域专用 hub。
3. **通用检索**：中英文各一次 + 仓库搜索，记下关键词和命中。

最后一行必须是结论：**完全匹配 / 部分匹配 / 没有**。

## 判定

| 结论 | 动作 |
|---|---|
| 完全匹配 | 用现成的；写清怎么装、有什么取舍，不动手自研 |
| 部分匹配 | 复用它，只补最小缺口，缺口写出来 |
| 没有 | 说明搜过什么，再写，保持最小实现 |

## 反模式

- 一上来就逆向目标软件的内部实现，再设计自己的方案。
- 用「感觉快做完了」的深挖，替代十分钟检索。
- 只问需求细节（做什么），不问发现性问题（有没有现成的）。

## 报告模板

```text
本地：<查了什么，有没有>
生态：<查了哪个目录，有没有>
检索：<关键词，命中几个>
结论：完全匹配 / 部分匹配 / 没有 → 采用 X / 补 Y / 自研
```
