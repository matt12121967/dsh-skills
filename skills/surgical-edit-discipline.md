# 外科手术式修改

低级错误的大头往往不在于不会写，而在于**改的时候手太重**：顺手把全角引号改成半角、把「」换成 ""、把破折号换成 --、把缩进重排、把没让你改的句子润色一遍。用户看到的是「又给我改坏了」。

## 改前

1. 读原文，确认**最小改动范围**：哪几行、哪个片段。
2. 记下这片区域的格式约定：全角还是半角标点、引号用「」还是 ""、缩进 2 还是 4。
3. 拿不准能不能动的地方，列出来问，不猜。

## 改中

- 只替换目标片段，**周围一个字符都不碰**。
- 不重排、不折行、不删空行、不「顺手统一」标点。
- 批量替换前先数命中数；数和预期不符就停。
- 中文文本保持原标点：`，。；：？！「」『』（）——……` 不换成 `,.;:?!""()--...`。

## 改后（必须做）

有 git 时，只应看到预期的那几行变化：

```powershell
git diff --stat
git diff -U0 <file>
```

没有 git 时，做字符级自证：

```powershell
(Get-Content $p -Raw).Length                     # 长度变化应与改动量相符
Select-String -Path $p -Pattern '「|」|——'        # 关键标点还在不在
```

## 报告

一句话交代：改了哪几处、没动哪些、用什么验证的。**「已修复」不算报告。**

## 反模式

- 用整段重写代替定点替换
- 以「格式更统一」为由改无关行
- 改完不复跑、不看 diff 就说完成
- 批量替换后不核对命中数
