# 先核实，再下结论

没有事实源的模型会「补全」出一个合理但不存在的事实。抵抗它的不是更努力地想，而是给每句话标上来源等级。

## 三档声明

| 档 | 含义 | 报告里必须带 |
| 跑过 | 我执行了，看到输出 | 命令 + 关键输出 |
| 读过 | 我打开了文档、源码或页面 | 链接或路径 + 行号 |
| 推测 | 以上都没有 | 明写「推测/未验证」+ 怎么验 |

把推测写成陈述句，是这类错误最常见的形态。三者混排而不标注，等于全部降级为推测。

## 硬规则

1. **外部事实查原文**：版本、价格、地区支持、API 行为，打开官方页面确认。记忆里的「应该」经常是上一个版本。
2. **判定「被拦/被封/不可用」必须有对照**：换出口、换客户端、换账户跑同一个请求，看差异。没有对照叫现象，不叫结论。
3. **一次成功不等于普遍成立**：单点通过只能说「这条路径通过」。
4. **失败要能自证**：打印原始值（hex、repr、完整响应体），不转述成「大概是编码问题」。
5. **改完必须复跑**：修了 A，就把触发 A 的那条命令再跑一次，用输出说话。

## 报告模板

```text
结论：<一句话>
证据：<命令/输出/链接>
未验证：<还差什么，怎么验>
```

留白比编造便宜。说「这一项我没验证」不会让任务失败，编一个通过才会。
